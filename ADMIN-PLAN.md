# Админка фотографий: план реализации

## Что уже готово

Фаза 1 закрыта и работает в проде:

- `content/slots.ts` — реестр **105 слотов**: ключ, подпись, группа, пропорции
  места на десктопе и мобильном, `sizes`, `alt`, тип (фото/логотип).
- `content/media.json` (v2) — что сейчас показывается: путь, размеры, набор
  ширин, опциональный `focal`. Шесть слотов уже с `focal`.
- `public/media/` — 105 папок, 21 МБ. Имя файла содержит хеш содержимого,
  раздача с `Cache-Control: immutable`.
- `components/Media/MediaImage.tsx` — рендер по ключу слота, srcset,
  `object-position` из `focal`.
- `scripts/optimize-media.mjs` — конвейер сжатия: EXIF-поворот, набор ширин от
  реальных пропорций места, WebP 88 (фото) / 92 (логотипы).

Админки нет. Авторизации в проекте нет вообще: ни `middleware.ts`, ни сессий.

## Решено (2026-09-22)

| Вопрос | Решение |
|---|---|
| Язык интерфейса | **Русский.** Клиент им владеет. Подписи слотов в `slots.ts` остаются как есть. Локали — если понадобятся, отдельной задачей. |
| Кто выкатывает в прод | **Клиент сам, сразу.** «Опубликовать» → коммит в `main` → автодеплой. Ради этого инструмент и делается. Страховка — откат одной командой: каждая публикация это ровно один коммит. |
| Фото мельче, чем нужно слоту | **Предупреждать, но разрешать.** Показывать «нужно 2400px, у вас 800px — будет нечётко» и давать опубликовать. Апскейла не делаем никогда. |

## Два требования, которые определяют архитектуру

**Изменения публикуются пачкой.** Клиент правит сколько угодно слотов, потом
жмёт один раз — один коммит, одна пересборка. Не «замена = деплой»: при
обновлении двенадцати плиток Inspiration это двенадцать сборок и двенадцать
промежуточных состояний сайта.

**Кадрировка видна до публикации на настоящей странице.** Не в абстрактной
рамке в админке, а там, где фотография реально окажется, с настоящей вёрсткой,
на десктопе и на телефоне. Иначе клиент публикует, видит обрезанное лицо, и всё
переделывается заново.

Оба требования упираются в один вопрос: **где живёт черновик**. От ответа
зависит и пакетность, и превью.

## Где живёт черновик

**Решение: отдельная ветка в репозитории, которая не деплоится.**

Каждое изменение слота — коммит в ветку `media/draft`. Публикация — один коммит
в `main`, собирающий всё накопленное. Ветка после этого сбрасывается.

Почему так:

- **Переживает всё.** Закрытая вкладка, другой компьютер, севший ноутбук.
  Клиент может собирать подборку два дня и не потерять её.
- **Нового хранилища не нужно.** Git уже есть, он уже умеет версии и откат.
- **Публикация честно одна.** Собираем дерево поверх текущей головы `main`,
  один коммит, одна сборка.

Альтернатива — держать черновик в браузере (IndexedDB). Проще, но час работы
клиента исчезает от очистки данных браузера или смены устройства. При требовании
«иначе быть беде» это неподходящий размен.

Ветку `media/draft` надо исключить из сборок Vercel, иначе каждое сохранение
черновика будет запускать превью-деплой. Настраивается через Ignored Build Step
или `vercel.json`.

## Как выглядит превью

Два уровня, оба нужны.

### Уровень 1: слот, мгновенно

Фотография в пропорциях слота — ровно тех, что в `slots.ts`, с тем же
`object-fit` и `object-position`. Десктоп и мобильный рядом, потому что у части
слотов пропорции разные. Точка кадра ставится кликом, рамка пересчитывается
сразу.

Ловит большую часть проблем и не требует ничего, кроме данных, которые уже есть.

### Уровень 2: настоящая страница

Страница сайта в iframe, в которую подставлены черновые фотографии.

Работает так: `MediaImage` начинает выводить `data-slot="<ключ>"` на теге.
Админка открывает iframe своего же origin, находит в нём `[data-slot]` и
подменяет `src`/`srcset` на черновые. Скрипта в самой странице не нужно — origin
один, админка дотягивается до документа напрямую.

Ширина iframe переключается между десктопом и 390px. CSS страницы отрабатывает
как обычно, то есть клиент видит настоящую кадрировку, а не её имитацию.

**Это требует правки заголовков.** Сейчас стоит `X-Frame-Options: DENY` и
`frame-ancestors 'none'` — наши страницы нельзя показать в рамке даже самим
себе. Нужно `SAMEORIGIN` и `frame-ancestors 'self'`. От кликджекинга с чужих
сайтов это по-прежнему защищает, но изменение осознанное и его надо отметить.

**Слоту нужно знать свою страницу.** В `slots.ts` нет поля «где показывается».
Добавляем `page` — путь для превью. Мелкая правка реестра, без неё уровень 2 не
собрать.

## Прочие решения

### Авторизация

Один общий пароль в переменной окружения, сессия в подписанной куке.

- `POST /api/admin/login` сверяет пароль через `timingSafeEqual`, выдаёт
  `HttpOnly; Secure; SameSite=Lax` куку с HMAC-подписью и сроком.
- `middleware.ts` пускает только с валидной кукой.
- Ограничение попыток входа, чтобы пароль не подобрали перебором.

**Важно:** `matcher` ограничить строго `/admin/:path*` и `/api/admin/:path*`.
Middleware выполняется на каждом попадающем под matcher запросе; захватив весь
сайт, мы потеряем ту статику, ради которой переделывали рендеринг. Проверяется
замером, не на глаз.

Ни пароль, ни токен GitHub в браузер не попадают.

### Отдельный аккаунт GitHub для записи

Токен берётся **не с основного аккаунта**. Причины:

- Коммиты от админки будут подписаны этим аккаунтом. В истории репозитория
  сразу видно, где правка человека, а где замена фотографии из админки.
- Утёкший токен — это утёкший доступ конкретного аккаунта, а не твоего.
- Отозвать доступ можно, не трогая свою учётку и не ломая себе рабочий доступ.

Два варианта, оба рабочие:

**Машинный аккаунт.** У вас уже есть `traumerch-dev` — ровно такой случай.
Fine-grained токен от него, права «Contents: write» на один репозиторий.
Просто и знакомо.

**GitHub App.** Правильнее: токены короткоживущие и выписываются на лету,
права объявлены явно, установка только на нужный репозиторий, коммиты
атрибутируются приложением. Настройки больше, зато нет вечного токена в
переменных окружения.

Предлагаю начать с машинного аккаунта — он уже есть и разницы в поведении
админки нет. На GitHub App можно перейти позже, это замена одного модуля
выдачи токена.

### Ограничение на размер загрузки

Тело запроса к serverless-функции Vercel ограничено примерно **4.5 МБ**.
Фотография с телефона весит 8-15 МБ — наивная загрузка упрётся в лимит на первом
же реальном файле клиента.

Поэтому уменьшение происходит **в браузере до отправки**: canvas до 2560px по
длинной стороне (конвейер всё равно не делает шире), JPEG q92 — обычно меньше
2 МБ. Нужно учесть EXIF-ориентацию
(`createImageBitmap(file, { imageOrientation: "from-image" })`), иначе фото с
телефона ляжет набок.

### Коммиты

Git Data API: блобы → дерево → коммит → перевод ветки. И для черновика, и для
публикации — набором вызовов, атомарно.

Старые варианты слота удаляются тем же коммитом, иначе `public/media` растёт с
каждой заменой.

Публикация собирает дерево поверх **текущей** головы `main`, меняя только пути
медиа. Поэтому параллельный пуш разработчика не создаёт конфликта.

### Куда коммитить

Репозиторий и ветка — из переменных окружения. На дев-стенде дев-репа, в проде
прод-репа. Один код, разная настройка, тестировать можно не трогая прод.

## Шаги

Каждый проверяется отдельно, следующий не начинается пока предыдущий не сошёлся.

### 1. Конвейер сжатия в общий модуль

Правила качества и ширин живут в `scripts/optimize-media.mjs`. Админке нужно то
же самое — вынести в `server/media/optimize.ts`, скрипт начинает импортировать.

*Проверка:* `npm run media:optimize` даёт побайтово тот же `media.json` и те же
файлы. Поведение меняться не должно.

### 2. Реестр и разметка под превью

Поле `page` в `slots.ts` для всех 105 слотов. `data-slot` в `MediaImage`.
Заголовки `SAMEORIGIN` / `frame-ancestors 'self'`.

*Проверка:* страница открывается в iframe со своего же origin; у каждой картинки
есть `data-slot`; сайт снаружи по-прежнему не встраивается.

### 3. Авторизация

Логин, кука, middleware, ограничение попыток.

*Проверка:* `/admin` без куки и с подделанной кукой не пускает; пароль не
перебирается. Отдельно: `/catalog`, `/quote`, `/faq` остались
`x-vercel-cache: HIT` и не замедлились.

### 4. Админка на чтение

105 слотов по группам, текущая фотография, вес, размеры, подпись.

*Проверка:* видны все 105, ни один не потерялся относительно `slots.ts`.

### 5. Черновик: загрузка, кадрировка, превью уровня 1

Выбор файла, уменьшение в браузере, сжатие на сервере, коммит в `media/draft`.
Слот в пропорциях, точка кадра кликом, десктоп и мобильный рядом.

Список «что изменено» с возможностью отменить отдельный слот.

*Проверка:* загрузить тяжёлое фото с телефона — не упирается в лимит, не легло
набок. Закрыть вкладку, зайти с другого браузера — черновик на месте. Сборки
Vercel при этом не запускаются.

### 6. Превью уровня 2

iframe настоящей страницы с подменой черновых фотографий, переключение
десктоп/мобильный.

*Проверка:* подменённое фото видно на реальной странице в реальной вёрстке;
кадрировка совпадает с тем, что получится после публикации.

### 7. Публикация

Один коммит в `main` со всем накопленным, сброс черновика, обратная связь по
сборке.

*Проверка:* на дев-репе. Изменить три слота, опубликовать, увидеть **один**
коммит и **одну** сборку. Дождаться, сверить с превью. `git revert` возвращает
все три обратно.

## Чего не будет

**Управление размером слотов.** Клиент управляет только точкой кадра. Размеры
задаёт вёрстка — решение принято раньше.

**Добавление новых слотов.** Новый слот = запись в `slots.ts` плюс
`<MediaImage slot="..." />` в разметке. Работа разработчика.

## Риски

**Middleware может съесть статику.** Самый серьёзный. Сайт только что переведён
на готовый HTML с CDN; неверный `matcher` вернёт всё в serverless. Проверяется
замером на шаге 3, до того как поверх появится UI.

**Ослабление защиты от встраивания.** `frame-ancestors 'self'` вместо `'none'` —
осознанный размен ради превью. С чужих origin встраивание по-прежнему запрещено.

**Репозиторий растёт.** Git хранит все версии каждой фотографии. При 105 слотах
и нечастых заменах это надолго не проблема, но растёт монотонно.

**Задержка публикации.** Между кнопкой и сайтом 1-2 минуты пересборки. Свойство
схемы, а не недоработка — клиенту сказать сразу, иначе будет жать повторно.

**Брошенные черновики.** Клиент может начать и не закончить. Ветка будет висеть
с недоделанным. Нужен явный показ «есть неопубликованные изменения» и кнопка
сброса.

**Токен даёт запись в репозиторий.** Только в переменных окружения на сервере,
в браузер не отдаётся. Отдельный аккаунт, права минимальные — «Contents: write»
на один репозиторий, не полный `repo`.

## Что нужно от тебя

Перед шагом 3 — переменные окружения в Vercel:

| Переменная | Что это |
|---|---|
| `ADMIN_PASSWORD` | пароль входа |
| `ADMIN_SESSION_SECRET` | случайная строка для подписи куки |
| `GITHUB_TOKEN` | fine-grained, с отдельного аккаунта, «Contents: write» на один репозиторий |
| `GITHUB_REPO` / `GITHUB_BRANCH` | куда коммитить |
| `MEDIA_DRAFT_BRANCH` | ветка черновика, по умолчанию `media/draft` |

Плюс настройка Vercel: исключить `media/draft` из сборок.

Значения ставишь сам, я их не вижу и не записываю.
